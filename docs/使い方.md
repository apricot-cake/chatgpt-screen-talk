# 使い方・設定・データの扱い

必要な環境、起動、画面共有と音声会話の基本操作は[README](../README.md)を参照してください。

## Windowsでの起動

ZIPを展開したフォルダーの `start.cmd` をダブルクリックします。初回は必要なパッケージを導入してビルドし、サーバーの応答を確認してから既定のブラウザを開きます。以後は依存やソースに変更がある場合だけ準備をやり直します。

Node.jsやCodexが見つからない場合は、表示された手順で導入してから起動し直してください。ChatGPTへのログインが必要な場合は `codex login` を実行します。APIキーの認証から自動で切り替えることはありません。

起動中のウィンドウで `Ctrl+C` を押すとサーバーを終了します。ブラウザが自動で開かない場合は、ウィンドウに表示されたURLを開いてください。

## 画面共有と音声会話

画面共有、会話の開始・終了、会話の文字起こしは一つのページにまとめています。同じタブを開いたまま、共有したアプリで作業を続けられます。

画面共有と音声接続は独立しています。画面共有を停止すると画像取得だけが止まり、会話は続きます。会話を終了するとマイクと音声接続が閉じ、画面共有は続きます。両方を終える場合は、それぞれ停止してください。

マイクで話した音声だけを音声会話に使います。共有したアプリの音やゲーム音は取得しません。

## 設定

| 環境変数    | 用途                                                        | 既定値                     |
| ----------- | ----------------------------------------------------------- | -------------------------- |
| `CODEX_BIN` | Codexの実行ファイルまたは公式JSエントリーポイントの絶対パス | `PATH`から探索             |
| `PORT`      | ローカルサーバーのポート番号                                | 空いているポートを自動選択 |
| `DATA_DIR`  | 実行時データの保存先                                        | `.data/`                   |

Windowsの例:

```powershell
$env:CODEX_BIN = (Get-Command codex.exe).Source
$env:PORT = '57259'
npm start
```

Windowsの標準npm配置にある `codex.cmd` にも対応します。独自配置のshimを使う場合は、`CODEX_BIN`に実際の実行ファイルか公式 `codex.js` を指定してください。

## データの扱い

共有画像はローカルで最新の1枚を更新します。音声セッションは、画面に関する質問に答える際にその画像をツール経由で取得します。会話中のマイク音声と、参照した共有画像は、回答生成のためOpenAIへ送信されます。

`.data/`には共有画像、共有状態、接続先アドレス、音声受信の診断値を保存します。このフォルダーと画像・録音ファイルはGitの追跡対象から除外しています。認証ファイルやAPIキーをリポジトリへコピーしないでください。

このアプリの音声セッションに、開発時のチャット履歴は自動で引き継がれません。

## 確認状況と制限

元の試作では、ユーザーがマイク入力、返答音声の再生、共有したゲーム画面を参照した音声回答を確認しています。TypeScript版では、型チェック・ビルド・ローカルHTTP・音声接続処理のmockを検証しています。ReactによるUI統合後のマイク入力と返答音声の実接続は別途確認が必要です。

- 音声機能は実験的なApp Serverプロトコルに依存し、互換性が変わる場合があります。
- 共有画像を更新し、質問に応じて参照する方式です。
- 小さい文字やツールチップを読み違える場合があります。
- サブスク利用枠の消費量や料金を、このアプリ独自に確定することはできません。

関連する仕様は [Codex App Server](https://learn.chatgpt.com/docs/app-server) と [ChatGPTの利用枠](https://learn.chatgpt.com/docs/pricing) を参照してください。
